# SYNAPZ Solana Foundation Showcase — Codex Build Specification

## Objective

Build a production-quality, standalone **Solana Foundation Showcase module** for SYNAPZ.

This is not a whitepaper and not a generic registry browser. It must be an interactive technical showcase that presents:

1. the **full completed SYNAPZ end-state architecture**;
2. the **current proof/evidence state**;
3. the **gap between the two**;
4. the **Solana-specific integration path**;
5. the **engineering evidence and maturity boundaries** behind every current-state claim.

The finished module will be integrated into the existing private SYNAPZ Technical Atlas/Replit app only after Codex has completed implementation and verification independently.

---

## Core story

The showcase must communicate one coherent system:

**SYNAPZ / OMEGA**
→ **PRIME CORE**
→ **7 brain functions**
→ **1,024 logical-capacity node fabric**
→ **simulation / evaluation / governance / controlled execution**
→ **Solana data + execution integration**
→ **multichain**
→ **markets / trading**
→ **wallet / payments**
→ **NFT / digital assets**
→ **tokenisation / RWA / regulated issuance**
→ **settlement**
→ **application layer**

### Critical truth boundaries

- PRIME Core is the central governed intelligence/control plane.
- The seven brains are functional stages/modules, not seven personalities.
- The seven named brain functions are:
  1. Self-Model
  2. Instinct Router
  3. Simulation
  4. Memory
  5. Specialists
  6. Evaluation
  7. Governance
- 1,024 means logical-capacity architecture/target, not 1,024 live physical servers or processes.
- FULL VISION may show target architecture.
- CURRENT PROOF may only show approved + published reviewer-visible evidence supplied by the host adapter.
- QUALIFIED != DEPLOYED.
- TESTNET != MAINNET.
- PAPER/SHADOW != live trading.
- PLANNED/TARGET != implemented.
- Never imply Solana Foundation endorsement.

## 16. Tests

Unit/integration tests must cover:
- all seven brain names;
- 1,024 disclaimer;
- Full Vision vs Current Proof behavior;
- target architecture does not imply implementation;
- CURRENT PROOF excludes unapproved records;
- tier cannot be escalated via client input;
- no private draft body shown in owner preview;
- maturity boundaries;
- current-vs-completed separation;
- roadmap unfinished labels;
- Solana path;
- Copilot prompt set;
- no admin/write actions;
- evidence links only to visible evidence;
- no unsafe identifiers in demo fixtures.

E2E:
- load showcase;
- switch Full Vision / Current Proof;
- open PRIME;
- traverse seven-brain flow;
- open 1,024 explainer;
- traverse Solana path;
- inspect current-vs-completed;
- inspect roadmap;
- open evidence;
- verify narrow/mobile layout;
- direct refresh/deep link if routing is included.

Adversarial:
- try to make CURRENT PROOF reveal draft fixtures;
- try to pass higher reviewer tier from client;
- inject instruction text into evidence fixture;
- attempt admin navigation/action;
- verify fail closed.
